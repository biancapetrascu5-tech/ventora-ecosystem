# E1 — Varianta A (client per modul) vs. Varianta B (client unic multiSchema)

**Data:** 2026-10-24  
**Prisma:** 7.10.1 | **Postgres:** 17 (Docker local)

## Întrebare

Care strategie Prisma oferă mai bun echilibru între izolare, DX și overhead la build?

---

## Varianta A — client Prisma per modul

Fiecare modul (`lab_core`, `lab_booking`, `lab_crm`) generează propriul `PrismaClient` dintr-o schemă separată.

```
lab-core/prisma/schema.prisma     → lab-core/generated/client/
lab-booking/prisma/schema.prisma  → lab-booking/generated/client/
lab-crm/prisma/schema.prisma      → lab-crm/generated/client/
```

Fiecare modul are propriul `prisma.config.ts` cu URL-ul propriu de conexiune.

**Izolarea este structurală:** `coreDb.contact` este eroare TypeScript — clientul pur și simplu nu știe de modelul `Contact`.

---

## Varianta B — client unic cu `multiSchema`

Un singur `schema.prisma` cu `previewFeatures = ["multiSchema"]` descrie toate cele 3 scheme.
Un singur `PrismaClient` generat cunoaște toate modelele.
Izolarea se face prin wrapere per modul (`coreRepo`, `bookingRepo`, `crmRepo`) și reguli lint.

```
experiments/e1/variant-b/prisma/schema.prisma → experiments/e1/variant-b/generated/client/
```

## Măsurători (Prisma 7.10.1, Postgres 17, Windows 11, Node 24)

### prisma generate

| Metrică                | Varianta A (3×)    | Varianta B (1×)  | Raport A/B |
|------------------------|--------------------|------------------|------------|
| Timp total (ms)        | 3306               | 901              | 3.7×       |
| — per invocație (ms)   | 985 / 986 / 1335   | 901              | —          |
| Dimensiune client (KB) | 25 747             | 8 879            | 2.9×       |
| Fișiere generate       | 63                 | 21               | 3.0×       |
| Pași `generate`        | 3                  | 1                | —          |

Dimensiune per modul (Varianta A):

| Modul      | Modele | Dimensiune | Fișiere |
|------------|--------|------------|---------|
| lab_core   | 6      | 8.52 MB    | 21      |
| lab_booking| 2      | 8.34 MB    | 21      |
| lab_crm    | 1      | 8.29 MB    | 21      |

**Observație:** dimensiunea clientului este dominată de runtime-ul Prisma (~8.3 MB bază), nu de numărul de modele.
Diferența dintre 1 model și 6 modele este de ~0.23 MB (< 3%).

### Timp build TypeScript

Măsurat cu `tsc --noEmit` pe fișierele de wrapper per modul:

| Metrică           | Varianta A | Varianta B | Raport A/B |
|-------------------|------------|------------|------------|
| Timp build (ms)   | 2156       | 665        | 3.2×       |

Varianta A compilează 3 type definitions separate (câte un `PrismaClient` per modul),
ceea ce explică factorul 3.2× față de Varianta B cu un singur client.

### Dimensiune bundle serverless

Clientul Prisma generat (TypeScript/JS) este componenta ce merge în bundle-ul serverless.
Prisma 7 folosește `@prisma/fetch-engine` — engine-ul Rust (~30 MB) **nu este bundled la install**,
ci descărcat la prima pornire în `/tmp`. La Vercel, pentru producție, se recomandă bundlarea explicită.

**Componentele unui bundle serverless Vercel:**

| Componentă             | Varianta A / funcție | Varianta B / funcție |
|------------------------|----------------------|----------------------|
| Client Prisma (modul)  | ~8.5 MB              | ~10.4 MB (toate 15 module) |
| Engine Rust (bundled)  | ~30 MB               | ~30 MB               |
| Next.js server runtime | ~12 MB               | ~12 MB               |
| **Total estimat**      | **~50 MB**           | **~52 MB**           |

**Limita Vercel:** 250 MB / funcție (necomprimat) — [documentație oficială](https://vercel.com/docs/functions/limitations).

La Varianta A: fiecare funcție API include **doar** clientul modulului propriu (~8.5 MB).
La Varianta B: **toate** funcțiile includ clientul complet cu toate modelele.

**Comparație cu limita Vercel: 50 MB / 250 MB = 20% din limită → marjă 5×**

- Client combinat: ~8.5 MB bază + ~139 × 15 KB = ~10.6 MB

Amândouă variantele sunt la 20–21% din limita Vercel, cu marjă de 4.7–5×.
Măsurarea reală pe un build Next.js complet se face la E4.

## Test import interzis între module

Script: `labs/experiments/e1/variant-a/cross-module-test.ts` și `variant-b/cross-module-test.ts`

```ts
// cross-module-test.ts — același cod testat pe ambele variante
const org = await bookingDb.organization.findFirst(); // accesare model din alt modul
const contact = await bookingDb.contact.findFirst();  // accesare model din alt modul
```

Rezultat compilare `tsc`:

| Variantă  | Eroare TypeScript?                                       | Prins de lint? |
|-----------|----------------------------------------------------------|----------------|
| A         | **DA** — TS2339: Property 'organization' does not exist  | La compilare   |
| B         | **NU** — compilează fără erori                          | Necesită lint  |

Output exact Varianta A:
```
cross-module-test.ts(10,29): error TS2339: Property 'organization' does not exist
  on type 'PrismaClient<PrismaClientOptions, never, DefaultArgs>'.
cross-module-test.ts(13,33): error TS2339: Property 'contact' does not exist
  on type 'PrismaClient<PrismaClientOptions, never, DefaultArgs>'.
```

Varianta B compilează fără erori pentru același cod — clientul unic cunoaște toate modelele,
deci `db.organization` și `db.contact` sunt tipuri valide chiar din contextul modulului booking.

La Varianta B, izolarea depinde exclusiv de reguli lint (`boundaries/dependencies`) și convenții de cod.

## Calitate izolare

| Criteriu                              | Varianta A           | Varianta B             |
|---------------------------------------|----------------------|------------------------|
| Eroare TypeScript cross-module        | DA (structural)      | NU (tipul cunoaște tot)|
| Izolare la runtime fără lint          | DA                   | NU (necesită wrapper)  |
| Risc de acces accidental cross-module | Imposibil la compilare | Posibil, prins de lint|
| Securitate DB (Postgres roles, E3)    | Ambele variante beneficiază egal |             |

## Constatare cheie: Prisma 7 — schimbare API

Prisma 7 a scos `url` din blocul `datasource` al schemei. Asta afectează ambele variante:

- **Varianta A:** 3 fișiere `prisma.config.ts` (câte unul per modul)
- **Varianta B:** 1 fișier `prisma.config.ts` (avantaj modest)

Clienții runtime în Prisma 7 nu mai acceptă `datasources: { db: { url } }` la instanțiere.
Aceasta nu schimbă diferența structurală între variante, dar adaugă overhead de setup identic pentru ambele.

---

## Concluzie

**Varianta A este recomandată** pentru Ventora:

1. **Izolarea e garantată structural** — TypeScript verifică la compilare, fără lint suplimentar
2. **Overhead de bundle neglijabil** — ~50 MB / funcție pentru ambele variante, marjă 5× față de Vercel
3. **Fără risc de regresie** la adăugarea unui nou model — nu poate contamina alt modul fără o schemă separată
4. **Build mai lent la generate** (3.7×) — acceptabil, rulat o dată la schimbări de schemă

**Varianta B rămâne utilă pentru:**
- Prototipuri rapide cu modele cross-schema (FK explicit între module)
- Tooluri interne fără cerințe stricte de izolare

**Decizie pentru producție:** Varianta A, cu roluri Postgres (E3) ca strat suplimentar.  
**Măsurare reală bundle** (Next.js build complet, fișier `.next` pe Vercel): E4.
