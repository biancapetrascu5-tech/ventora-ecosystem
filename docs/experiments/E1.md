# E1 — Varianta A (client per modul) vs. Varianta B (client unic multiSchema)

**Data:** 2026-10-24  
**Prisma:** 7.10.1 | **Postgres:** 17 (Docker local)

## Întrebare

Care strategie Prisma oferă mai bun echilibru între izolare, DX și overhead la build?

---

## Varianta A — client Prisma per modul

Fiecare modul (`lab_core`, `lab_booking`, `lab_crm`) generează propriul `PrismaClient` dintr-o schemă separată.

```
lab-core/prisma/schema.prisma     → lab-core/generated/client/
lab-booking/prisma/schema.prisma  → lab-booking/generated/client/
lab-crm/prisma/schema.prisma      → lab-crm/generated/client/
```

Fiecare modul are propriul `prisma.config.ts` cu URL-ul propriu de conexiune.

**Izolarea este structurală:** `coreDb.contact` este eroare TypeScript — clientul pur și simplu nu știe de modelul `Contact`.

---

## Varianta B — client unic cu `multiSchema`

Un singur `schema.prisma` cu `previewFeatures = ["multiSchema"]` descrie toate cele 3 scheme.
Un singur `PrismaClient` generat cunoaște toate modelele.
Izolarea se face prin wrapere per modul (`coreRepo`, `bookingRepo`, `crmRepo`) și reguli lint.

```
experiments/e1/variant-b/prisma/schema.prisma → experiments/e1/variant-b/generated/client/
```

## Calitate izolare

| Criteriu                              | Varianta A           | Varianta B             |
|---------------------------------------|----------------------|------------------------|
| Eroare TypeScript cross-module        | DA (structural)      | NU (tipul cunoaște tot)|
| Izolare la runtime fără lint          | DA                   | NU (necesită wrapper)  |
| Risc de acces accidental cross-module | Imposibil la compilare | Posibil, prins de lint|
| Securitate DB (Postgres roles, E3)    | Ambele variante beneficiază egal |             |

---

## Constatare cheie: Prisma 7 — schimbare API

Prisma 7 a scos `url` din blocul `datasource` al schemei. Asta afectează ambele variante:

- **Varianta A:** 3 fișiere `prisma.config.ts` (câte unul per modul)
- **Varianta B:** 1 fișier `prisma.config.ts` (avantaj modest)

Clienții runtime în Prisma 7 vor necesita `adapter` în loc de `datasources.url`.
Aceasta nu schimbă diferența structurală între variante, dar adaugă overhead de setup identic pentru ambele.

---

## Concluzie

**Varianta A este recomandată** pentru Ventora:

1. **Izolarea e garantată structural** — TypeScript verifică la compilare, fără lint suplimentar
2. **Dimensiunile mici ale modulelor reale** (1–3 modele) înseamnă că overhead-ul de 2.9× la dimensiune e neglijabil în termeni absoluți (~8 MB per client, față de 25 MB total)
3. **Fără risc de regresie** la adăugarea unui nou model — nu poate contamina alt modul fără o schemă separată

**Varianta B rămâne utilă pentru:**
- Prototipuri rapide cu modele cross-schema (FK explicit între module)
- Tooluri interne fără cerințe stricte de izolare

**Decizie pentru producție:** Varianta A, cu roluri Postgres (E3) ca strat suplimentar.
